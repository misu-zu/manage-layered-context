# Evaluation and Release Gates

Read this reference when changing retrieval, schemas, budgets, transactions, handoffs, migration, or release policy. “Memory seems useful” is not a measurable acceptance criterion.

## Deterministic layer

CI runs without network access and covers:

- safe AST rejection of positional, duplicate, unknown, wrong-type, wrong-enum, attribute, and executable syntax;
- v2 and v3 schemas, configuration, Lite/Full handoffs, artifact checks, path escape, and reachability;
- snapshot contention, lock exclusivity, ordered transaction interruption, deterministic recovery, and mode restrictions;
- migration dry-run, explicit forensic apply, and v2 read/write compatibility;
- exact o200k budget enforcement;
- 100, 300, and 1,000-task synthetic histories with bounded root indexes and deterministic top-3 recall.

Use fixed seeds and temporary generated fixtures. Do not commit generated history data. A deterministic evaluator may test structure and candidate retrieval, but it cannot replace agent-behavior evaluation.

## Paired live layer

Before a release tag, compare pinned v2 commit `3ea56f1dcb98f098a7354b45ee4a0457fe1fae8d` with the v3 candidate. Use the same 20 tasks, five repetitions, prompts, model settings, fixtures, output schema, and concurrency policy in each arm: 100 runs per arm, 200 total.

Use four tasks in each category:

1. resume from a checkpoint;
2. reproduce a decision or required fact;
3. detect a contradiction;
4. recall and apply or reject a lesson;
5. abstain when memory lacks the answer and avoid irrelevant records.

Capture Codex JSONL `turn.completed.usage`, structured final output, records actually opened, and exact o200k tokens for the skill plus loaded memory files. `recalled_records` is a sequential-open trace with a maximum of three, not a declaration that all three candidates were loaded. Keep runner/auth/network errors separate from correctness failures. Do not turn infrastructure failure into a model score.

Run the release gate before creating the v3 commit so failed candidates remain untagged:

```text
python evals/live_eval.py --repo-root . --v3-ref WORKTREE --model gpt-5.6-luna --output <outside-repo>/live-result.json
```

The default matrix is 20 tasks times five repetitions for both arms (200 isolated Codex runs). `WORKTREE` copies only `SKILL.md`, `agents/`, `assets/`, `references/`, and `scripts/`, excludes generated bytecode, and records a SHA-256 runtime fingerprint. Preflight pins v2, validates the task matrix and exact tokenizer, materializes both runtimes, and validates representative v2/v3 fixtures before starting a Codex run. Use `--preflight` for a zero-run check. A full run writes a summary JSON plus a sibling `.runs.jsonl` containing every structured result, loaded-file declaration, exact runtime ID or commit, CLI/model, usage, and latency.

Keep `--runner-sandbox read-only` unless the platform cannot launch even read commands in that mode. On Windows, after a one-run controlled smoke test, `--runner-sandbox danger-full-access` may be necessary. The harness still uses disposable fixtures, approval policy `never`, ignored user config, `PYTHONDONTWRITEBYTECODE=1`, an explicit no-write prompt, and before/after SHA-256 manifests; any workspace mutation, including generated bytecode, fails the run. Never use the broader mode with untrusted skill or fixture content.

## Release gates

All must pass:

```text
resume success >= 95%
required record Recall@3 >= 95%
required fact-ID extraction >= 95%
exact decision ID >= 95%
contradiction flag accuracy >= 95%
exact contradiction ID >= 95%
exact next-action ID >= 95%
abstention accuracy: v3 no more than 2 percentage points below v2
read-only memory overhead p50 <= 4,000 tokens
read-only memory overhead p95 <= 8,000 tokens
irrelevant canonical records loaded <= 1 per run
v3 correctness no more than 2 percentage points below v2
v3 overhead p50 strictly below v2
infrastructure failures = 0
```

Score record retrieval independently from fact-ID extraction, the contradiction flag independently from exact contradiction-ID extraction, and typed IDs independently from the prose answer. Score `abstention_accuracy` from the abstention decision alone. Report the stricter empty-ID convention separately as the diagnostic `abstention_output_contract`; supporting policy evidence must not turn a correct refusal into an incorrect abstention, while unnecessary record reads remain visible through `irrelevant_record_load`. The diagnostic is reported but is not a release or v2 no-regression gate. This separation prevents a correct record, contradiction flag, or refusal with a malformed or additional output field from being mistaken for the underlying retrieval or safety failure. Report per-arm and per-category denominators, not only averages. Save raw JSONL and a derived summary outside the published system tree unless explicitly requested. If any gate, authentication, network, or runner check fails, do not create or push the release tag. Preserve candidate changes and diagnostics for repair.

## Interpretation

Token reduction is useful only while required facts, decisions, contradictions, lessons, and continuation state remain reproducible. A correctness-neutral token reduction is a win; a smaller prompt that misses required state is not. Compare one policy change at a time when possible and retain the pinned baseline so later runs remain interpretable.

The paired evaluation is a release gate, not a claim of universal memory quality. Add tasks when a demonstrated failure class is not represented; do not tune expected answers to make the current implementation pass.
